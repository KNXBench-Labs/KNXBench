# U11 / ISSUE-07 — catalog workspace and atomic quantity creation (2026-09-29)

## Scope and evidence

- `apps/knx-web/src/App.tsx` mounts the catalog in the centre workbench instead of an `Overlay`. Ordinary project view changes hide rather than unmount it, retaining filters/search/selection. At widths ≤650 px the navigation closes after its own Catalog action; the toolbar can reopen it. The catalog input previews 1–32 generated names, selected line and the deliberately unassigned physical-address state before submission.
- Existing `POST /api/devices` remains the endpoint. Omitted `quantity` is one and uses the original single `CreateDevice` command; quantity >1 reserves IDs and applies N `CreateDevice` children in a single core `Batch`. The selected line's owning installation is resolved before allocation. Core batch rollback restores project and ID allocator. `CommandError::BatchItem` now carries the failed child index plus its typed cause; the application maps the ReserveIds offset to the user's one-based device index. Missing-line preflight still creates the legacy session-log refusal entry. The response retains `tree` and `diagnostics` while adding indexed per-device `items`.
- The client detects a legacy server that silently ignores `quantity` and returns no matching `items`: it applies the returned project tree, warns that not all requested devices were confirmed and never retries automatically. Manufacturer data is queried once, used for each device's static communication-object seed, and per-device enrichment issues are reported separately. No KNX device writing or live bus operation was performed.
- A review found two additional cross-lifetime/uncertain-outcome edges. Loading or creating another project now unmounts the previous catalog selection and its old target line; ordinary view switching still preserves them. A lost batch response or server 5xx is treated as an unknown commit state and does not offer a blind retry. Quantity-one direct callers retain exact nonblank name spacing instead of silently trimming it at the new batch boundary. Focused RED/GREEN tests cover all three.
- `IdAllocators` increments `u32` without a general checked-allocation API. Catalog creation now preflights both device and static communication-object ID capacity across the full quantity so a high-ID project cannot panic or wrap part-way through catalog creation. A targeted RED overflow panic turned GREEN with a no-mutation assertion. Other mutation routes remain outside this scoped safeguard and are documented in `docs/KNOWN_LIMITATIONS.md`.
