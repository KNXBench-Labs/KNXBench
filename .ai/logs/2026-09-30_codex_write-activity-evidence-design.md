# Commissioning write-activity evidence boundary — 2026-09-30

- Agent: codex. This is an architecture/review package, not a new write feature. No Web source or live KNX hardware was touched; the other session's Web lock remains in force.
- Audited actual server/protocol code for `POST /api/device-address/by-serial`, `POST /api/device/service-control` and `POST /api/bus/write`. HTTP 200 can mean no change for both device procedures; post-send failures/cancellation can be ambiguous; a group telegram sent through the tunnel has no per-device verification. The serial-address HTTP route currently persists no pre-write recovery artifact; its response `previousAddress` cannot survive a dropped request. The service-control backup only covers the property value and mask.
- ADR-0056 sets a separate typed write-evidence contract: `running`, `noChange`, `notSent`, `sentUnverified`, `verified`, `unknown`, with phase-aware producer hooks at the write boundary, not blanket mapping from `Result`. It is not implemented yet. Recovery IDs must be guarded references to persisted evidence, never paths/keys/raw payload. These write routes remain explicitly untracked; `coverage: partial` is retained. No new live permission is implied.
- Simulated HTTP regression tests assert an accepted group send does not become a device receipt, a serial-address request can return 200 with `wrote: false`, and a service-control request can return 200 with `written: false` and no second backup. No access key was guessed or recorded.
