# 2026-10-07 — Claude — knx-server terminates TLS itself (ADR-0088)

## How it was decided

A grill-me session with the user (German), four rounds:

| # | Question | Decision |
|---|---|---|
| Q1 | What to protect | Browser ↔ `knx-server` only. "SSH" was a slip for SSL. KNX IP Secure stays out (KL §26). |
| Q2 | Reach | LAN and VPN. No internet claim. |
| Q3 | Desktop shell | Untouched (loopback, in-process). |
| Q4 | Built-in vs. proxy | Built in (rustls). The user's container runs `--network host`, so a proxy would leave the plain port open beside it. |
| Q5 | Certificates | Self-signed generated by default, own PEM files optional. |
| Q6 | When on | Automatically when a password is set; `KNX_TLS=off` with a loud warning. |
| Q7 | Plain HTTP on the TLS port | First-byte detection, `307` redirect. |
| Q8 | Cookie | Always `Secure` over HTTPS. |
| Q9 | Storage | `/data/.knxbench-tls`, locked away from every route. |
| Q10 | SAN/validity | Loopback + host name + `KNX_TLS_SAN`; 825 days; renew under 30 days; restart to reload. |
| Q11/Q12 | Broken / expired own files | Broken refuses to start; expired starts with a warning. |

## Facts verified, not assumed

- rustls 0.23 `with_single_cert` → `CertifiedKey::from_der` → `keys_match`:
  a mismatched key is already a config error (pinned by a test).
- `aws-lc-sys` carries the OpenSSL licence → `ring` provider everywhere.
  `cargo deny check` green afterwards.
- Apple: 825 days, SAN names, EKU serverAuth, SHA-2 apply to user-added
  roots too (support.apple.com/103769; the 398-day limit is preinstalled
  roots only, /102028).
- axum 0.8 `serve::Listener` trait lets a custom listener plug into
  `axum::serve`; axum built without `http2` → ALPN `http/1.1` only.
- `x509-parser` shows up in `Cargo.lock` (optional rcgen dep) but is not
  built; validity is read with ~20 lines over `yasna` instead.

## Code

- `apps/knx-server/src/tls.rs`: pure decision (`TlsSwitch`, `resolve_tls`,
  `prepare_tls`).
- `tls_cert.rs`: SAN parsing/validation, generation (rcgen), PEM loading,
  validity via yasna, fingerprint, private atomic writes.
- `tls_listener.rs`: accept loop + per-connection handshake task (10 s),
  channel to `axum::serve`; plaintext `307`/`400` with byte-checked
  host/path.
- `paths.rs`: `refuse_reserved` on every resolver incl. absolute paths and
  symlinks; `fs_routes.rs` hides the directory in the root listing.
- `auth.rs`: "cookie not Secure" notice moved to `cookie_secure_notice`
  (it depends on the later TLS decision).
- `main.rs`: reads `KNX_TLS*`, the host name from
  `/proc/sys/kernel/hostname`, prints `listening on https://…`/`http://…`.

## Pitfall hit while smoke-testing

A backgrounded *shell function* (`run ./knx-server &`) makes `$!` the
subshell, so `kill $!` left the server alive and the next runs failed to
bind and answered from the stale server with an old in-memory certificate.
Use `exec` inside the function. Also: in a debug build, `KNX_AUTH_PASSWORD`
hashing at 600 000 iterations takes several seconds; pass a precomputed
`KNX_AUTH_PASSWORD_HASH` for quick smoke runs.
