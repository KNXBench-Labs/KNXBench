## Acceptance

- Three English native projects: home 32 devices/105 GAs, six-flat residential
  101/339, office 157/507. All 290 parameter/program views resolve after the
  fictional catalogue's real UI install into an initially empty catalogue.
- 966 named UI checks; five exercises each, including acknowledged description
  and parameter edits, new inferred-DPT reserve link and save-as/reopen.
- An independent full-model comparison reconstructs all four intended edits
  with core commands and rejects every other content difference. Only the
  legitimate project modification timestamp is normalized. Read-only practice
  inputs and exact full-model re-save/reopen are separately verified.
- Catalogue install: 12 members, 9 products/programs, 0 unknown/conflicts;
  repeated upload deduplicates. No firmware, signatures or vendor payloads.
- Server/Chromium run inside a separate user/network namespace with loopback
  only; no gateway or existing live server/catalogue is used. The application's
  existing startup-discovery request fails 502 there; no operational bus request,
  external browser request or page exception occurred. The standalone server
  and browser are stopped and absence verified at task closure.

## Diagnostics retained in the local log

Early catalogue drafts declared unnecessary master metadata that the adapter
reported unknown/unsupported. They were removed from the original synthetic
authoring input, never hidden or discarded from a user import. The final install
is clean. Early verifier attempts exposed native-option visibility, asynchronous
onboarding, a scalar conflict count and a void save response; those harness
attempts are not counted as successful acceptance.

The guide replaces unavailable device renaming with the supported description
edit and explains inferred rather than editable group DPTs and native auto-save.
These boundaries are in the project guides and engineering contract.

Review is local **self-review**, not an independent-agent approval. Baseline and
final full-model tests, malformed/address/link/DPT/refusal controls, deterministic
ZIP/source/checksum tests, affected application regression, style/build and
repository/documentation gates are recorded in `delivery-verification.json`.
