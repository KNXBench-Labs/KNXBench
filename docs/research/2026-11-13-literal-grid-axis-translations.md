# Literal program-owned grid-axis translations — 13 November 2026

## Evidence and separation

The owner admitted an own-word behavioral contract after an ETS6 6.4.1 offline
observation of a fictional single-device project. The independent implementation
role received that contract, not the product package, original XML, screenshots,
application internals or observation captures. Public regressions use newly
written fictional texts and identities over KNXBench's existing synthetic helpers.

## Bounded observation

A program-owned Table declared row and column captions with German translations.
The displayed headings followed their own translations in declaration order. A
column without the requested translation retained its own source caption beside
translated headings. Toggling one ordinary activation control hid and restored
conditional child controls without changing those captions. Reopening the editor
and project retained the restored configuration and captions. The owner reported
that the retained manufacturer data was unchanged; the inactive state differed by
one parameter override and the restored state had none.

This admits literal caption selection, not ETS internals or universal layout
compatibility. It does not establish Grid-specific visual behavior, translation
matching/empty-text policy, module or Repeat captions, parameter references,
placeholders, collapse/inline/nested layout rules or Button actions. No bus,
download or physical-device operation was involved in the observation.

## Independent implementation policy

Use the existing exact/one-way-prefix product-language policy, including its
lexical tie-break, explicit-empty distinction and own-source fallback. Those are
existing KNXBench policies, not additional claims inferred from this observation.
Bind axes to the hash-checked retained source and the stored program tree before
looking up their own Program-scoped `Text`. Refuse ambiguous identities and
nonliteral captions rather than borrowing a block, parameter or module caption.
