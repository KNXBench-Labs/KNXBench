## Method and original fictional witnesses

Both sessions ran an actual native Wayland/WebKitGTK window, with separate
loopback-only networking, read-only host root/input ZIPs, masked real home and
project paths, and private HOME/XDG/results. Live observations of each native
PID established those boundaries and the same executable digest across restart.
The original `usr/bin/knx-desktop` ELF was recovered from the authenticated
AppImage without rebuilding or replaying the UI; its SHA-256 equals both live
process observations. Those exact executable bytes are retained separately.
There were no mocked responses or direct SQL/project mutations; SQLite was used
read-only as an independent saved-result oracle. Both ordinary closes exited
zero, with the exact native process and windows absent afterward.

The [public fixture record](../evidence/wp11-positive-native-fixtures-2026-10-27.json)
contains both exact input ZIPs as base64, their member identities and the original
fictional demo-builder recipe. Neither is manufacturer data, an allocated vendor
identity, firmware or a device to program:

- `M-7FF1` is a no-hint control: a source-20 `TypeNumber` with default `2`,
  bounds `0…240`, no `UIHint`. It reached the existing generic fallback and
  retained the original value; that is not positive specialized-editor evidence.
- The separate `M-7FF2` witness declares `UIHint="Slider"` on the same bounded
  unsigned eight-bit type. Its program/ref/type ownership and hint were
  independently reviewed before positive execution. The actual installed source
  blob was then compared byte-for-byte with the tested ZIP member. The first
  control and both input ZIPs remained unchanged.

The relevant source-reader/editor-policy files were proved byte-identical to
the Alpha 17 artifact's source. Product creation seeded static data only;
dynamic/module activation and programmability are not claimed. Both fictional
