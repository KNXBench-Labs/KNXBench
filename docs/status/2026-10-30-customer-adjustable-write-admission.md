The [contract](../contracts/customer-adjustable-write-admission.md) fixes a
conservative KNXBench policy, not recovered ETS customer-rights or token grammar.
An exact unqualified `CustomerAdjustable` occurrence in the selected application's
own root parameters, direct Union members or explicitly traversed module contexts,
or `CustomerAdjustableParameters` in its own root `Static/Options`, blocks regular
App write preparation regardless of value. Both module anchors and nested
admitted module edges are included. Module-local Options, prefixed-only attributes,
Dynamic/Extension and arbitrary wrappers remain excluded matcher contexts.
Absence of a match is not evidence of general programmability or write safety.
The existing research records the [public-source rationale](../research/2026-10-30-customer-adjustable-write-admission.md).

Exactly two regular App guards follow kind/plug-in checks and precede image/plan
preparation. Actual CLI, HTTP Plan/Start and Web EN/DE consumers retain the typed
`customer-adjustable-parameters` reason with counts/classes only, without raw
values, IDs or occurrence paths. Complete and concretely requested partial/Changes
scopes, valid complete/partial restore and source-freshness checks inherit the
refusal; no-pending Changes stays no plan. Read-only preparation and low-level
plan/executor APIs remain unchanged: this is not a global capability barrier for
arbitrary library callers. Unknown/raw source retention and existing explicit
unsupported diagnostics remain; no data/schema/history migration or repin is added.

## Limits and remaining work

No hardware, real bus, analysis VM, deployment or release operation was performed.
No new device/family admission, Secure, authorisation, retry/wait or recovery
semantics follow from this refusal. It neither implements calibration-preserving
writes nor changes experimental configured System-2 admission.

**PRG-01 remains IN PROGRESS; KL-007 remains open.** Broader inactive/default/Union
and customer-rights semantics, wider identity/runtime layouts and memory rules,
whole-mutation effects/recovery and historical 105-fixture/category/opt-in
provenance remain unresolved. A separately reviewed source/design proposal for
an inactive-marker policy is not implemented or credited by this result; it is
not this package's contract. See the [open-work record](../open-work/PRG-01-programming-gaps.md).

This report describes the accepted runtime above, not a later documentation
commit. Result-document changes and publication/readback require their own
delivery verification; neither changes the binary attribution or establishes
hardware, deployment or release acceptance.
