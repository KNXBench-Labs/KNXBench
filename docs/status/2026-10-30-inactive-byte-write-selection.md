## Implemented behavior

- The regular App prepares a positive selected plan; the existing executor sends
  it. Supported closed numeric Choose/When evaluation can omit a byte only when
  all eight bits belong exclusively to a proved inactive aligned eight-bit field.
  Current and source-default selection topology must agree exactly. Active Union
  winners, necessary literals and source-protected bytes retain their prior rules.
- The independent source-default-1 oracle writes exactly `4400h: 01`,
  `4402h: C7 53`, `4405h: 68`, with no direct application data write to `4401h`.
  The source-default-0 control remains positive. Source Data/Mask, stored inactive
  values, unknown data and read-only image/Compare/Probe behavior are preserved.
- Complete, concrete Partial and Changes preparation, offline support/readiness,
  CLI and HTTP Plan/Start/source-freshness consumers share the selection boundary.
  No-pending Changes still prepares nothing. Counts reflect actual plan data
  writes after scope derivation, not the original image's writable size.
- Unsupported ownership, shared active/inactive bytes or different default
  topology produce the payload-free `inactive-write-selection` category and
  closed reasons. New refusals precede connector/frame activity; EN/DE guidance
  explains the limitation without exposing XML, identifiers, values or paths.
- Format 4 requires a typed, known, non-null `write_selection`. New regular
  captures bind `source-default-inactive-whole-bytes-v1`; historical restore uses
  `source-mask-only-v1`. Formats 1–3 require that field to be absent and select the
  historical generator by version. Reading format 1/2 does not grant restore
  eligibility: existing application/exemplar guards still apply. Exact ordered
  region/identity/shape checks remain, without cropping, padding or trying both
  generators. Backup-of-historical-restore is format 4 explicitly bound to the
  historical generator; its original backup stays byte-identical.
- Historical hardware evidence is reused only for an identical complete ordered
  old/new plan after the same concrete Partial derivation and existing evidence
  checks. Changed selection is `Untested` with the actual CLI/HTTP acknowledgement;
  identical and unchanged group-address-only controls retain applicable `Verified`
  evidence. No old hardware run is relabelled as testing the new policy.

## Executed evidence and attribution

The evidence below comes from retained real executions and parent-authenticated
source/artifact records, not predicted results. This documentation pass did not
run tests, compilers, gates or hardware operations.

   regular source-default-1 writer failed its intended assertion with exit 101;
   the source-default-0 imported control passed. The unchanged independent oracle
   now passes through real preparation, executor frames, active-byte landing,
   backup and readback. This is a positive implementation, not just a refusal guard.

   This is a different epoch from the namespace proof below, not an additive total.
3. **Expanded namespaces and genuine old catalogues:** nine methods failed their
   semantic assertions and three genuine KNX-prefix controls passed before the
   namespace correction. The same twelve methods passed afterwards; the four
   test-source files remained identical. The proof resolves actual inherited,
   rebound, default-reset and unbound contexts in hash-checked original XML and
   matches its ordered local-kind inventory to the retained tree. It does not
   infer cleanliness from local names or NULL opaque attributes.
4. **Real pre-correction provenance:** a retained pre-namespace CLI imported an
   original schema-20 package before recompilation. Its unchanged original
   database was genuinely reopened before correction and later exercised through
   App, offline preparation, the built CLI and HTTP. Known actual KNX prefixes
   still execute the fixed positive frames, excluding a blanket prefix or old

   independently seeded old bytes different from requested data. Existing exact

Execution receipts record isolated non-root, loopback-only operation, no
