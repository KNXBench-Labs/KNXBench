## Implemented boundary

The App validates immutable original format-3 evidence, then tries the existing
exact-pin original-project admission. Strict success retains its current-request,
exact-reference and dependency-mask path without global package discovery. Later
current-project refusal is terminal. Only the two enforcing typed source-binding
phases may dispatch the changed-source comparison; arbitrary `io::Error`, matching
text, unknown/unsupported/budget/read/transaction failures cannot do so.

The new private comparison supports both original selector families and namespaces
20/23, with the original profile cloned/reparsed and only actual source plus
same-family selector pins changed. The selected parsed ApplicationProgram `Name`
value alone may change: double quotes, nonempty printable ASCII, at most 1,024
bytes, excluding entities, tag delimiters and quotes. Full-document admission and
measured unique winners still apply; every other XML byte and hardware source is
exact. Full original-request preparation, typed record/coverage equality, exact
normalized values/serialized plan/Core plan and derived reconstruction fields
precede current-project preparation and the existing dependency mask.

Standalone discovery refuses at a second distinct retained package hash without
filtering invalid or missing candidates to obtain a convenient winner. Physical
inventory reuses production ZIP preflight, parser binding and checked decoding,
including empty directories, raw/resolved names, central order, local-record
order, flags, kinds, modes and every member byte. The new comparison also requires
validated local-record ranges (including data descriptors) to cover every byte
from offset zero to the central directory without a prefix, gap or unindexed
record. This is **not** a new restriction on ordinary package installation or an
already successful exact-pin path. It conservatively also requires
both raw extra-field sequences and mode bits exact. Thus changed extra-field
metadata or permissions refuse even when non-executable; ordinary recompression,
ZIP comments and header timestamps can differ when otherwise admitted. Retained
members never discover a package or invent historical archive membership.

The private result contains comparison bytes only. Start still uses original
pins. Historical recovery still validates original journal/prestate and separate
consent without a live-catalogue freshness gate. No schemas, ProductDB version,
protocol, dependencies, existing hardware/procedure policy IDs, timeout budgets or
original records change.
