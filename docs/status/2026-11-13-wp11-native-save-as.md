# WP-11 — Native Save As cells, 13 November 2026

## Result and source boundary

The actual native Wayland/WebKitGTK desktop passed twelve **Save As** subcells:
Cancel, Save, overwrite Cancel and Replace at 80%, 100% and 150% application
scale. An ordinary process restart and native Open preserved the three exact
fictional note edits and scale 150%. The reopened output's hash and modification
time remained unchanged. The [measurement](../evidence/wp11-native-save-as-2026-11-13.json)
records this finite matrix.

This is a fresh build of source `38d7ad5f5`, current at the observation's original
admission, with native schema 21. It is **not** a run of later `main`: the closeout
source `99a78fe35` contains CLI runtime changes, so the documentation-only reuse
rule does not rebind this evidence to it. No production code changed in this
package. Wider WP-11 and ledger status remain open.

## Executed native paths

At each scale, the real Tauri/GTK chooser was used, not a mocked chooser or an
HTTP replacement for the save action:

- **Cancel:** no output appeared and the settled project state was unchanged.
- **Save:** exactly the chosen filename was created without a duplicated suffix;
  SQLite integrity, schema 21 and the fictional project's identity were checked.
- **Overwrite Cancel:** the alert named a separate pre-existing output in the
  selected folder. Cancel followed by chooser Cancel preserved that target's
  exact bytes and nanosecond modification time; the new note was absent.
- **Replace:** the same alert's Replace action changed the target's bytes and
  modification time, preserved project identity and saved the exact new note.
  The project became clean and the journal reported saved state. The three
  replaced targets remained stable through the rest of the run and closure.

Each overwrite target was separate from the active project. This matters because
the background journal may save a confirmed edit in the active file before a
chooser is opened; an unchanged-active-file assertion would be an invalid
Cancel oracle. Saved journal state and stable samples preceded file comparisons.

Native keyboard zoom shortcuts established 100%, 80% and 150%, corroborated by
settings and control geometry. Both ordinary closes and launcher exits were
successful. Relaunch used the identical executable and frontend, then native
Open read back all three exact note titles and bodies with scale 150% persisted.
Opening the original schema-10 fictional input initially left its disk bytes
unchanged while the in-memory projection reported schema 21; the first Save As
created schema-21 output. Merely opening it is not claimed to rewrite the input.

## Evidence and limitations

The parent revalidated the retained source archive, executed binary identity,
660 retained file hashes, the exact twelve distinct matrix identities, six
saved SQLite outputs, Cancel/Replace discriminators and restart assertions.
Relevant native images include actual Save/overwrite dialogs at 150%.
These are artifact checks of the recorded execution, not a second GUI replay.

The execution used isolated fictional data, a read-only host root, private
project/profile paths, a loopback-only network namespace, dropped capabilities
and an explicit software-render profile. Shared Wayland, session D-Bus/AT-SPI
and the observed GVFS session-bus fallback are disclosed exceptions; full
host-service or WebKit sandbox attestation is not claimed.

Initial harness failures remain separate: an incorrect disk-schema assumption,
a tuple/list comparison after an already successful Replace, and offscreen
controls at 150%. The reader was corrected against retained outputs; exact-node
scrolling with a fresh visibility check completed only missing native actions.
No product defect was found within the executed assertions.

Owned native processes, windows, output and IPC were retired and runtime rules
disabled. Regular workspaces, focused monitor and cursor were restored. An
initially active screensaver disappeared, so **full seat restoration is not
claimed**. No real project, bus, physical device or ETS operation was involved.

This slice does not establish the remaining editor/focus, capture, pointer,
layout or hover cells. Orca, Firefox, AppImage/GPU and other desktop environments
remain the documented untested boundaries of the owner-fixed acceptance target.
