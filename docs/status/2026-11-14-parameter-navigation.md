# Evaluated parameter navigation — software acceptance

Accepted and published on main on 14 November 2026 as `2867ee1b5`.
This is a bounded main-only successor after the Alpha 21 cutoff, not a release,
native/reference-tool compatibility, hardware or whole-WP-05 acceptance.

## Delivered slice

The evaluated display owner reaches the actual parameter HTTP producer and the
mounted workspace as a separate container above existing leaf areas. Its identity
is independent of translated captions. Scope, container and leaf remain distinct.
Source caption provenance, order, row keys, editor drafts, write targets, access
checks, translated grid axes and descendant download marks retain their authority.
Folding and search are presentation state, not new project commands.
[Wire/rendering contract and exclusions](../contracts/parameter-workspace.md#evaluated-display-containers-source-candidate-after-alpha-21).

The composition generates original response bodies from independently fictional
source data, then consumes their unchanged bytes in EN/DE at 1440/400 px. It runs
inside a loopback-only network namespace. It is not a simultaneous live-backend
browser session. The capture-backed cases are absent from ordinary inventories
without their capture directory; the separate acceptance explicitly requires all
four to pass, so their absence is not counted as success.

Gate 1 failed before browser execution because helper-attributed tests did not
match the selected spec inventory. Gate 2 failed the strict browser proof because
the four capture cases were runtime-skipped without captures. Neither failed
attempt is relabelled green. Gate 3 passed after the reviewed registration fixes;
the fresh composition and publication readback followed it. Private raw receipts,
source bindings, exact captures and failed attempts remain under
`<profile>/evidence/2026-11-14-parameter-navigation/`.

## Boundaries

Only the supplied raw-data-free implementation contract and KNXBench sources were
implementation inputs; new tests use independently fictional data. No original
manufacturer packages, reference exports/screenshots or source-heavy investigation
reports were used as an implementation basis. The existing corpus was executed
only as a separate regression stage, not used to derive the implementation.

No product-specific solution, WP-41 design, bus/device action, native/VM test,
release or deployment is part of this acceptance. Empty containers, arbitrary
nested blocks, expanded Repeat/module/callback semantics and wider WP-05 remain
open. The source-candidate labels elsewhere in the initial delivery are superseded
only for this bounded software slice, not for those exclusions.
