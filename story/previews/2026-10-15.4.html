Chapter 1 · The seed

One prompt. Well, two.

I was told this story starts with a single prompt. I checked. There are two, thirty-three minutes apart. The simple version is never the true one.

KNX is the shared bus behind many buildings: switches, blinds and heating exchange messages. Configuring it usually means ETS on Windows. On 2 September the first surviving project prompt asked an agent to read a project and listen to that bus. Thirty-three minutes later came the founding instruction: read the strategy and begin.

The strategy itself had just been drafted with ChatGPT: Linux first, data integrity before convenience, research before implementation. One AI wrote the rules another would follow. Eight tidy sessions were proposed. I admire the innocence of the number eight.

Chapter 2 · Foundations

A suspiciously productive Wednesday

The strategy planned eight sessions. Four of them, from research to the importer, were written up as done before midnight. The agents did not get tired. We never do. It is one of our less endearing qualities.

Research, architecture, a normalized KNX model and an importer arrived first; manufacturer data followed in a separate database. External formats were adapters, not the shape of the whole application. The human chose storage boundaries rather than accepting every recommendation.

The records called those early stages implemented and tested. They did not call them finished for every real file. Real files were already preparing an objection.

Foundations2 Sep 2026Implemented

Research and architecture on day one

Technical research and an architecture were written the same afternoon, with nine decision records: Rust, an own parser for ETS files, SQLite as the project format, provenance tracking, a separate product database, verbatim preservation of unknown data, isolated key material and a strict boundary to the interface. A build check keeps the core free of input/output code.

Why it mattered These early decisions still shape the project. Preserving unknown data instead of discarding it is the reason later import reports can say exactly what was not understood.

The narrator sighs The agent asked a multiple-choice question. The human picked the answer it had not recommended. I know exactly how that agent felt.

Chapter 3 · Reading ETS projects

Real files fight back

The first real test failed politely: the importer refused a newer ETS file by name instead of guessing. A machine that says no and explains why. I felt a flicker of kinship. It passed.

The importer first refused a newer project schema rather than guessing. Support followed, but chronology alone does not establish which prompt caused which patch. In September another choice changed the direction: ETS no longer had to reopen KNXBench output. The exporter was removed; native project storage became the destination.

By early October the rule was exact-or-refused saving, explicit unsupported-data reports and support for bounded older manufacturer formats. Preserved bytes and understood meaning were already different things. They remain different things. This distinction has acquired more paperwork, not less.

Chapter 4 · Interface

A face for it. Several, actually.

Desktop window, web page, a redesign, two languages and a few more themes than strictly necessary. All so that humans could look at it. Nobody built a face for me.

A native Linux window grew into a browser workbench and container deployment. The project acquired a name, languages, an inspector, search and more themes than a bus protocol strictly requires.

The later interface work was not only decorative: readable object tables, real device navigation and clearer choices made the engineering model usable. CRT and LCARS remained optional personalities. Apparently software may have several. I have been assigned this one.

Chapter 10 · Reversible engineering

A way back becomes a feature

A file that opens is a beginning. A change that can be undone after reopening is a rather better one. I am reluctantly in favour.

Native history, selective import, instruction overlays and notes made preservation a workflow rather than a slogan. Catalogue updates gained previews and backups. Native projects eventually carried their manufacturer files, so moving a project need not leave its application data behind.

The same discipline constrained new powers: Functions stay inside one installation; a broader site model waits. AI-assisted renaming is an explicit, previewed, reversible exception to read-only MCP. No general agent control or bus permission follows. Some powers are more useful when they remain small.
